## Ticket 1 — Bill-title enrichment (highest value)

**Problem.** Voting records show the vote question — "On Passage", "On
Motion to Recommit" — where a voter expects a bill name. The data is
right; every vote direction was independently verified. Only the label is
useless.

**What exists.** `getBillDetail(congress, billType, billNumber)` in
`src/lib/api-clients/congress-gov.ts` already returns
`{title, latestActionText, latestActionDate}`. Nothing calls it.
`houseVotesToRows()` in `scripts/ingest/fetch_votes.ts` sets
`bill_title = vote.voteQuestion ?? 'House roll call N'`.

**⚠ The trap that makes this dangerous.** `bill_title` currently holds
the vote QUESTION, and `curate.ts` depends on that:

```ts
isProceduralVote(v.bill_title)  // src/lib/llm/curate.ts, ~line 223
```

That call is what stops the motion-to-recommit inversions this project
already shipped a fix for — three verifiers caught stances that read a
procedural vote backwards, in both directions. **If you overwrite
`bill_title` with the bill name, `isProceduralVote()` goes silent and the
inversion bug comes straight back, with no test failing to tell you.**

So: add a **separate** field (`vote_question`) carrying the question,
point `isProceduralVote()` at it, and only then let `bill_title` hold the
real title. Do it in that order.

**Acceptance (local code and tests):**
- [x] A vote row for a real bill displays the bill title, not "On Passage"
- [x] `vote_question` is preserved on every row, including Senate rows
- [x] `isProceduralVote()` reads the question field, and a test proves a
      motion to recommit is still flagged *after* enrichment runs
- [x] Rows with no resolvable bill (procedural-only roll calls) degrade to
      the current label rather than showing an empty title
- [x] Enrichment failure is non-fatal — a dead API call leaves the old
      label, never a blank card

## Ticket 2 — Citations should pin `roll_call_id`, not `bill_id`

**Problem.** A bill with several roll calls — a passage yea and a
motion-to-recommit nay — produces multiple rows sharing one `bill_id`. A
citation of that `bill_id` can resolve to the wrong row and display an
inverted vote. This is the same failure family as ticket 1.

**Where.** `src/lib/llm/curate.ts` builds its whitelist as
`validBillIds = new Set(candidate.voting_record.map(v => v.bill_id))`.
`VoteRecordRow` **already carries `roll_call_id`** (`fetch_votes.ts`
sets `house-{congress}-{session}-{rollCall}`), so the identifier you need
exists — it is simply not the one citations use.

Note `fetch_votes.ts` already dedupes on `roll_call_id` and throws on
contradictory positions for the same roll call. That guard is correct and
should stay.

**Acceptance (local code and tests):**
- [x] The synthesis prompt asks for and validates `roll_call_id`
- [x] Fabricated citations still throw (whitelist-only behavior preserved)
- [x] A test covers one bill with two opposed roll calls and proves the
      citation resolves to the right one
- [x] Existing stored citations stay unchanged; the decision is recorded
      below for the future commit

Decision: keep existing reviewed JSONB citations unchanged. The live card
does not resolve `track_record_citations` into vote rows. It renders the
reviewed note. Review artifacts show the stored identifier. New synthesis
runs require exact roll-call IDs, so the ambiguous behavior does not recur.

## Working notes that will save you time

**Verification is the product.** ~70 stances were refuted this run and
never reached voters. Every activation goes through: author from sources
actually read → mechanical validation → an independent **blind**
refutation-first verifier → the activation gates. A verifier who knows
the expected answer is not a verifier.

**Bot-blocking is not absence.** ballotpedia.org, house.gov,
congress.gov landing pages and several campaign sites return 403 or an
empty body to default fetch agents and 200 to a desktop browser
User-Agent. **A 403 is never evidence a page is missing.** clerk.house.gov
roll-call XML answers a browser UA and gives per-member votes — it is the
primary record for checking a vote citation.

**Never bypass TLS to read a source.** `ehrforcongress.us` fails
certificate name validation. A verifier read it with validation disabled
and reported different content; three legitimate reads agreed with the
original sourcing and the bypass was refused. A host that cannot prove
its identity is exactly the condition under which another site's content
gets published under a candidate's name. Cite the Wayback snapshot
instead — that is what Ehr's six stances do.

**Query the DB for content truth; bust the cache for render truth.**
WebFetch paraphrases, and its cache goes stale — a merged UI fix looked
unshipped until a `?cb=1` param busted it.

**FEC F3 reports are filed by the COMMITTEE, not the candidate.**
Querying `/candidate/{id}/filings` will tell you a well-funded candidate
has no financials. This cost real time and nearly deleted Bilzerian's
real $1.24M.

**Taxonomy changes do not re-file existing stances.** After any change to
`ISSUE_NAMES` in `src/lib/issues.ts`, re-run the slug audit across all
live stances *and* check `curate.ts` — the synthesis prompt builds from
`ISSUE_SLUGS`, and a hardcoded list there makes new slugs unreachable.
This drift will recur every single time.

**PowerShell here-strings break on apostrophes.** Write commit and PR
bodies to a file and use `git commit -F` / `gh pr create --body-file`.
`Set-Content -Encoding utf8` also mangles em-dashes; use the Write tool.
